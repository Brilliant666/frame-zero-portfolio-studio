## 结论

**保留价格页大外框。** 它给长内容提供了必要的边界。不协调主要来自浅白卡面、白字、细白边和明亮照片相互叠加，以及套餐内部的信息主次倒置。

Flow 的摄影背景、书法标题、荧光绿点缀、胶囊导航和细进度线已经形成统一身份。下一步应在这个身份内整理材质和阅读层级，保持现有照片、布局骨架与透明感。

## 优先问题

### 1. [P1] 价格条款的对应关系需确认

观察：介绍列出“半合成58.8”，第三张卡片列出“氛围特效38.8”；全包原价128.8，所述减28.8得到100，卡片却标最低98.8。它们可能是不同服务或不同活动组合，页面没有解释对应关系，不能仅据此判定哪个价格错误。

影响：访客即使读完也不容易确定实际服务和适用价格。

建议：由用户确认服务目录及最低价条件，再统一概览与卡片的表述。本轮不改商业条款。对应 Impeccable clarify。

来源：gallery.tsx:349；A/B 独立浏览器观察一致。

### 2. [P2] 套餐说明比名称与价格更抢眼，比较入口靠后

实测：套餐名称和价格12px，说明桌面26px、手机23px。1440×900 下套餐顶部约y764；1280×720下整组套餐在首屏之外。390×844 下三张卡片起点约y599、911、1143。

影响：先读到大段说明，真正需要比较的服务与价格反而像注释。不能把所有纵向滚动都当成问题，但当前信息顺序加重了比较成本。

建议：在大外框内部，建立“服务名 → 价格 → 服务范围 → 活动条件”的阅读次序；提高名称与价格权重，降低说明字号，给活动说明明确分组。先保留原文与全部条件，再确认内容重组。对应 Impeccable typeset / layout。

来源：gallery.module.css:23-24；A/B 同尺寸 DOM 测量一致。

### 3. [P2] 玻璃层的明暗与边框没有形成主次

观察：价格外框5%白色，内卡约4.3%白色，联系卡约9.4%白色；后面还有明亮、细节丰富的照片。白字、白边和亮底容易混在一起，卡片呈现一层发白的薄雾。导航已有相对稳定的中性偏绿玻璃质感。

影响：页面构成没散，但文字和卡片的边界不够稳定，用户感受到“不和谐”。

建议：保留价格大框，把它作为主要承载层；试做很轻的中性烟色透明底，让照片仍然清晰参与画面。内卡降低填充和边框权重。联系卡沿用同一材质，复制按钮保留44px热区和明确反馈，视觉上再轻一点。不要恢复此前大块深黑底，也不要一律加深全页背景。

这是需要看同照片对照的设计方向，不是已经确定的透明度数值。先做一组候选再判断。对应 Impeccable colorize / polish。

来源：gallery.module.css:3-6、23、67；A视觉与B浏览器证据相符。没有测量合成后对比度，不声称WCAG通过或失败。

### 4. [P2] 固定底部进度线与长内容相交

观察：390×844价格页，固定进度标记和线条穿过套餐说明；1280×720联系页也可能与较低的卡片相交。1440×900联系页留白充足，不能以此排除短屏问题。

影响：底部装饰打断正文阅读。仅增加页面末尾空白无法避免中途滚动时重叠。

建议：保留细线这个视觉元素；在价格/联系这类可滚动长内容中，让它有独立区域，或随正文流布局，避免始终悬浮在文字上。不要牺牲复制热区或移除价格大框来让位。对应 Impeccable adapt / layout。

来源：A现场观察、父级手机截图复核；gallery.module.css 的 sceneProgress 与 scene 规则。

## 访客路径与次要观察

- 初次访客：最容易在“概览和套餐是否对应、优惠怎么适用”处停下来。
- 手机访客：联系四卡在390×844内完整可见、无横向溢出；价格阅读需要多屏，底部进度线干扰更明显。
- 键盘访客：导航与复制控件有可见焦点。深链进入价格后标题出现的荧光绿矩形是焦点样式，不能当成装饰框直接删除。
- 三个导航、三个套餐、四个联系方式，没有超过四个的单组选择墙。负担主要来自信息对照和视觉主次。
- 浏览情绪：首页照片建立吸引力，价格阶段因小价格和条款关系降低理解流畅度；联系页直接但偏被动。
- 联系页先社交主页、后QQ/微信。若以后以咨询成交为主要目标，可再调整主次；当前“扩列”文案下，不能直接判定这个顺序错误。
- 手机顶部导航高36px，社交文字链接高21px；后续可扩大实际点击区，保留现在紧凑的视觉尺寸。未据此判定WCAG失败。
- 没有证据支持本轮额外增加动效；应先解决阅读、材质及遮挡。
