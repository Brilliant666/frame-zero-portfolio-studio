## 2. 基础共用后台的结论

**保留桌面的“槽位—当前照片—本站图库”工作区，调整入口与信息优先级。** 这里服务固定模板素材组合，与高级图集管理是不同任务。

| 基本资料 | 非空表单分组和输入区可用；手机单列，桌面有较宽表单 | 保留内容模型；精简视觉重复、给字段与实际页面位置建立简短对应，是设计建议，不是字段缺失 |

## 4. 高级拍立得后台的结论

**当前图库／图集职责正确，成员排序已不是旧版“选择操作＋手柄＋工具条”。** 需要调整的是照片之前的信息，以及图集设置的优先级。

| 任务 | 现场结论 | 推荐方向 |
| --- | --- | --- |
| 图库→图集 | 上传入口、独立内容共用本站照片说明、进入图集、方向／时间／关系筛选、分页与恢复均存在 | 合并重复图库标题、计数、用途；上传动作明确保留。限制与说明可放邻近可展开区域，不能删掉错误恢复或让上传限制到失败后才可知 |
| 新建／选片／排序／封面 | 入口顺序可辨认；本次打开已有图集，不新建或确认选片 | 保留选片关系与保存发布边界；不把“从图集移出”混成删除图库原图 |
| 成员工作区 | 实际 11 张成员卡，整卡拖动、独立看大图、键盘说明；源码有撤销。图片大图关闭返回原触发按钮 | 保留成果。未拖动落位，PR33 的 50/100 张模拟验证属于历史，不作为本轮长列表手感证据 |
| 图集设置 | 全部移出及重复效果入口出现在常用命名／封面之前；下拉候选主要靠素材序号／方向识别 | 先名称与当前封面缩略图，再效果细节；批量移出放清楚可达的成员管理区。评估缩略图选封面，不增一套模板引擎 |
| 当前对象预览 | 完整图集预览确实打开当前图集；关闭回原入口焦点。成员大图也恢复焦点 | 保持现有语义与返回连续性；区分局部效果、完整图集预览，减少重复入口，不删除完整预览 |
| 手机资料／套餐／联系 | 单列字段、套餐摘要／展开、可选联系卡实际可见；390 下主要字段宽 325、高 44，无页面横溢出 | 保留表单能力；固定双保存按钮继续保留。中途滚动截图不足以确认软键盘与最后字段遮挡，需后续实体设备检查 |

图库初始状态首张已解码照片位置：390×844 为 Y=1213.09、照片高 120，首屏可见面积 **0**；1280×720 为 Y=737.66、高 160，首屏可见面积 **0**；1920×1080 同 Y=737.66、高 160，整张高度可见。证据表明需减少任务前的信息占用，不能用缩小照片来“达标”，也不需改成 Flow 配色。

图集顺序、成员顺序、图库时间排序分别属于不同对象。现有标签与上下文已区分；应在局部调整时保留，不能为统一工具区而把三种排序合成一个控件。封面、重点照片及完整显示／裁切的控件本次只读；其改动后的实际构图需隔离数据专项验证，未在日常内容中触发。

| 套餐／联系 | 双主视口及联系 320；可达，实际联系内容与可选卡片可见 |
| 动态偏好 | 媒体模拟 reduced-motion=true 时图集进入／返回可用，之后清除模拟。工具未提供完整动画列表，未断言全部运动停止或 GPU 性能通过 |

结论：**保留风格和构图体系，仅讨论局部引导与内容适应。** 纸面温度、照片框与胶带不是装饰错误；夜空主题也不需要统一成 Flow 的透明照片背景。观察到的竖图大图和手机显示尊重完整照片，未找到支持全面重做布局的证据。

两项低优先建议：套餐行动文案“收藏这段旅程”实际指向联系，可能让人以为会收藏，后续可讨论更明确的咨询动词；当前联系标题为空时仍有较高标题区，属于内容条件，需与已填写标题的情况对照后再决定空白折叠。二者本轮均不改原文，不定性为功能失效。
