# 全平台设计与 UI 只读评审

日期：2026-10-12。状态：**COMPLETE_WITH_LIMITS**。本报告是范围确认材料，不是改版授权。

## 1. 执行摘要

当前产品已经拥有可辨认的摄影表达，而非十三套同色卡片页。高级拍立得的相纸与构图、Flow 的摄影背景与流动轨道、基础模板各自的叙事方式，应继续保留。三套后台也已呈现不同内容模型：基础槽位、拍立得图集、Flow 分类；没有理由强制合并业务流程。

本轮最明确的两项缺陷很局部：

1. **流体棱镜的空槽色轨撑宽手机网格，导致标题和介绍右裁切。** 390px 与 320px 现场可见；不是“中文字体不好看”的问题。
2. **高级拍立得夜空局部预览的主题切换按钮深字深底。** 后台通用按钮文字色覆盖预览主题文字色，源码与实际 computed style 一致。

其余主要机会是后台任务层级、手机照片工作区和模板挑选时的真实内容预览。它们属于体验判断或新提案，不应与上述确定缺陷一起打包成全平台重做。平台根介绍页、Flow 前台及已经收紧的高级状态栏，本轮建议保留。

重要限制：十一套基础模板均查看了桌面和手机结构，但当前合法实验室使用空库。只有当前基础草稿的 `character-select` 完成非空作品、大图及套餐联系路径；其余十套的非空效果没有被这轮证明。两套高级前台使用既有真实内容，未改动内容来凑覆盖。

## 5. 三套后台独立评审

### 5.1 基础后台

六分区均实际浏览：模板 E06–E07；资料 E05/E25；套餐 E08–E10；素材排版 E11–E12；联系 E13–E14；兼容工具 E15–E16。桌面与手机均有观察；只读展开套餐，不编辑字段。

**保留**：当前草稿与公开模板分开显示；模板挑选和素材槽位有连接；兼容工具仍能找到；固定保存操作可用。基础模板共用一个内容空间，不能将每张模板卡描述为另一份独立资料。

**B / 中可信度**：表单多层白底框、分区标题、组标题和说明竞争注意力；部分“添加”按钮与同页其他动作的边框、圆角、强调程度不一致。它没有使任务无法完成，但增加扫描负担。可围绕“当前任务—字段组—辅助说明”整理，不必更换字体或控件库。

**B / 中可信度**：手机素材排版首屏先经过状态、说明、槽位条，照片工作区较晚出现；这是具体任务密度问题，不等于页面长就是错。应保留槽位要求与换图上下文，避免照搬高级图集流程。

模板切换后真实内容的效果验证受只读边界限制：点候选卡可查看说明，但“选为草稿模板并进入素材排版”会改变内存草稿，本轮未点击。上传、换图、推荐排版、保存失败恢复等写入状态仅有源码背景，未现场触发。

### 5.2 高级拍立得后台

图库 PA01–PA02；图集列表、照片排序、图集设置、展示效果 PA03–PA09；资料 PA10；套餐/联系分别有桌面与手机记录。查看了命名字段、封面区域和选片入口，未选入、拖动、切封面、确认新增或展开文件上传。

**保留**：图库与图集分开，已有整卡排序；图集内的排序、设置、效果职责清楚；顶栏不再常驻旧的大块发布成功横幅；预览与保存发布没有混为一个动作。

**A / 高可信度**：夜空局部预览主题切换按钮颜色被覆盖，见 F2。此问题限定到该嵌入场景，不能说公开夜空全部不可读。

**B / 中可信度**：手机图库仍需跨过五模块导航、状态与筛选才能看到照片；桌面图集流程同时有返回、去图库、当前图集、步骤和提示，初次用户需要识别多个层级。建议调整任务相关项的出现位置，保留异常恢复和素材元信息，不再加新入口。

### 5.3 Flow 后台

图库 FA01–FA02；首页 FA03/FA04稳定帧；完整作品 FA05–FA07；价格 FA08稳定帧/FA09；联系 FA11稳定帧/FA10最终手机帧。五模块均实际查看；完整作品第二分类的预览和关闭实际走通。

**保留**：暖浅底与绿色动作区别于拍立得；首页字段说明了展示位置；价格/联系采用对象列表＋当前表单；分类预览为全屏真实效果，而不是常驻半宽模型。第二分类预览关闭后，仍在第二分类，焦点恢复到“当前分类效果”，没有必要重做这一条路径。

**B / 中可信度**：手机价格/联系对象列表为横向条带，再接纵向表单，方向变化有学习成本，但当前有滚动条和卡片边缘提示；尚不足以认定必须改成另一个导航。可保持，先观察真实用户是否找不到后续项目。

**本轮未覆盖**：大批量选片、真实上传异常、空分类/隐藏分类提示、删除恢复、并发冲突、保存发布加载/失败状态；未通过写入制造这些条件。

| F6 | D / 中 | 提供明确不会选为草稿的“用当前素材预览候选模板”可能更好 | 新能力提案；不是已有按钮失效，不得在本轮偷偷接入 |

### F1 的可复核原因

Prism 实验室九个 `.colorRailPlaceholder` 实测宽42.390625px；手机九列加间距后约420px。`.hero` 可视宽375px，但 computed `grid-template-columns` 为419.891px；`.heroCopy`、`.stage`、`.colorRail` 都约419.89px。标题右边界435.89px，介绍右边界432px，均越过375px。

源码：`app/templates/prism-liquid/template.tsx` 的空槽色轨；`template.module.css` 的 `.colorRailPlaceholder`、手机 `.colorRail`、`.hero`。手机规则缩小了真实按钮，没有同步缩小占位符；`1fr` 的自动最小值继续被色轨撑开。外层 overflow 裁掉越界，所以 document.scrollWidth 正常不能证明文字完整。证据：B05-root-cause、B05-overflow-fonts、B05-mobile、B05-prism-320。

### F2 的可复核原因

`app/preview-workspace/admin.module.css` 的 `.workspace[data-site-editor="premium"] button` 文字色优先级高于 `collection-live-preview.module.css` 的局部 toolbar button。背景继续使用夜空主题，文字却使用后台深色。证据：PA-night-button-style 与 PA-night-button-confirmed。未把透明背景单点采样包装成完整 WCAG 评估。

### 不宜升级成缺陷的取舍

- Film、Editorial 的标题和留白较大，可能服务叙事；没有非空同内容对照，不要求压缩。
- Neon、Orbital、Character 的暗色表达、Museum 的深木框、Archive 的文件系统隐喻各自成立。
- Flow 手机套餐/联系自然滚动，让信息保持可读；“一屏放完”不是共同目标。
- 相纸、胶带、星形、连线与倾斜不是天然多余。高级三构图提供不同观看节奏，保留。
- 照片背景上的文字可读性依赖素材与裁切；当前截图不能覆盖所有亮暗分布，暂不判定全站对比度合格。

## 9. 六项候选方案与顺序

### 方案 1：只修 Prism 手机空槽撑宽（推荐先做）

1. **事实/场景**：F1，合法空库模板在390和320发生实际裁切。
2. **影响**：摄影师还未填满照片时，标题/介绍就可能读不全；混合空槽风险需另外验证。
3. **证据/可信度**：现场截图、子项尺寸与源码，高。
4. **依据**：本项目独立布局分析；不借字体指南掩盖网格错误。
5. **推荐**：约束手机网格最小宽度，真实照片按钮与空槽使用相容尺寸；正文按实际容器换行。
6. **保留**：流体构图、色轨、字体、色彩和标题文本。
7. **成本/风险/损失**：小；小色轨可能缩小触点或间距，需检视交互，不能仅设 overflow:hidden。
8. **不改**：空库手机裁切持续存在。
9. **未来验证**：空库、部分空槽、满库；原短标题、长中文、中英标点；320/390/1440，检查字形边界、照片和色轨，不能只看 scrollWidth。

### 方案 2：隔离拍立得局部预览主题样式（推荐先做）

1. **事实/场景**：F2，仅内嵌夜空主题切换按钮被后台字色覆盖。
2. **影响**：切回纸面的入口难辨认，破坏预览可信感。
3. **证据/可信度**：截图＋computed style＋选择器优先级，高。
4. **参考**：Radix Colors 的文字/背景语义配对；不是采用其色值。
5. **推荐**：明确后台 chrome 与预览主题的样式边界，给局部按钮完整的主题状态。
6. **保留**：后台浅色、夜空前台、三构图及纸面配色；不重置所有 button。
7. **成本/风险/损失**：小；错误加大选择器可能影响禁用或焦点，需局部检查。
8. **不改**：按钮仍能点，但夜空预览的操作说明继续难读。
9. **未来验证**：三构图×两主题，桌面与局部手机；hover/focus/active，不扩成整个发布系统重测。

### 方案 3：清楚处理旧内部预览入口

1. **事实/场景**：F3，内部折叠区展示当前运行不可达的旧入口。
2. **影响**：内部评审者可能误以为所有预览坏了。
3. **证据/可信度**：界面存在、浏览器拒绝、边界源码，中高；具体 HTTP 响应本轮未取证。
4. **依据**：本项目能力与入口应一致的判断。
5. **推荐**：保留折叠区，但隐藏不适用于当前运行模式的入口，或明确不可用原因；不解封旧路由。
6. **保留**：安全边界、合法模板实验室及本人后台快捷入口。
7. **成本/风险/损失**：小；开发环境仍需该入口时应按实际能力展示，避免一刀切删除。
8. **不改**：内部人员继续遇到死路；公众主要登录路径未受影响。
9. **未来验证**：当前 Node 模式、允许该入口的开发模式，各自验证链接；不扩大权限。

### 方案 4：基础后台做任务层级整理，保留槽位模型

1. **事实/场景**：F4，六分区内部的框线、标题和说明密度仍高。
2. **影响**：初次编辑者需从多个视觉层级判断当前该做什么。
3. **证据/可信度**：E05–E16，体验判断中；没有量化用户研究。
4. **参考**：Practical Typography Headings 的结构优先；UI Playbook Button 的主次与状态区分。
5. **推荐**：每区一个任务标题，字段组用间距/简短组名；次要提示靠近对应字段；同页相同行为按钮用同一层级。优先资料与套餐两区验证。
6. **保留**：六分区、模板素材要求、保存发布、错误恢复、兼容工具；摄影前台样式不跟随后台统一。
7. **成本/风险/损失**：中；过度减少边界可能使组别更难分。备选是保留框线，仅收紧重复标题和操作样式。
8. **不改**：功能仍可用，扫描负担维持；不预言用户流失。
9. **未来验证**：让编辑者完成“找当前模板→改一组字段→预览→返回”的只读/隔离任务；比较找字段路径、误点及手机滚动，而非只测页面高度。

### 方案 5：手机照片任务前移，按页面条件精简

1. **事实/场景**：F5，基础素材排版、拍立得图库在照片前有较多控制层；不是所有后台同样严重。
2. **影响**：主要在手机找图/判断当前槽位时，需要先越过说明与导航。
3. **证据/可信度**：E11、PA01与桌面对照，中；首屏位置依状态，不复用旧报告数值。
4. **依据**：独立任务分析；不以图库 SaaS 截图规定照片尺寸。
5. **推荐**：当前槽位/选片目标保持可见，低频说明就近按需展开；仅在有关联目标时突出图集关系筛选。候选方向二是保持现布局，只缩短辅助说明的常驻面积。
6. **保留**：照片大小、上传限制、搜索筛选、元信息、分页、异常恢复及固定保存按钮。
7. **成本/风险/损失**：中；说明收起可能降低初次可发现性，不能重回大量三角折叠。
8. **不改**：手机多一次滚动即可继续，并非阻断；桌面不应为凑首图指标同步压缩。
9. **未来验证**：同数据同状态390/320，记录首张完整照片和无遮挡面积，检查键盘/弹窗及保存栏，听取初次用户反馈。

### 方案 6：不改草稿的候选模板真实内容预览（独立提案）

1. **事实/场景**：F6，实验室为空库，现有候选模板选择动作会改变内存编辑。
2. **影响**：摄影师无法充分判断自己照片与模板是否合适；本轮也无法只读完成十套非空覆盖。
3. **证据/可信度**：模板编辑器与实验室源码、合法路径检查，中高；收益为待验证假设。
4. **依据**：本项目使用流程，不是外部目录要求。
5. **推荐**：在选择卡提供语义明确的临时预览；只读映射已有素材，退出返回卡片与滚动位置，另一个明确动作才选为草稿。备选：仅给内部实验室提供批准的非私人固定样本，成本较低但不能替代客户照片预览。
6. **保留**：一个基础内容空间、槽位适配说明、私人访问控制和显式保存发布边界。
7. **成本/风险/损失**：中至大；涉及预览契约、素材映射和授权检查，不能作为按钮文案小改动。固定样本还会制造维护成本。
8. **不改**：现功能不因此错误，但模板比较仍依赖空结构或先选为草稿；评审结论需继续保留覆盖缺口。
9. **未来验证**：预览前后草稿修订/选中模板/Published不变；不同照片比例、缺槽位、退出焦点、跨站资源拒绝。先单独批准设计与权限范围。

建议顺序：**1＋2 局部修复 → 3 入口整理 → 4 或 5 选一个体验切片 → 单独决定 6**。本轮没有实施任何一项。

## 10. 保留、缺口与待确认

最值得保留的三项：

1. 十三套前台的独立表达，尤其拍立得相纸构图和 Flow 摄影玻璃层；不强制同色同字体。
2. 三空间独立内容、共享图库、单一 Published 主页及紧凑双状态；预览不替代发布。
3. 已有查看效果路径，尤其 Flow 分类定位及关闭返回，以及高级整卡照片排序的职责分离。

不建议照搬：通用 SaaS 仪表盘到摄影前台；把排版文章的禁斜体偏好应用到 Editorial；为了现代感增加新动画；把 Radix 的固定色阶当作照片背景对比度证明；引入组件库只为修一个按钮颜色。

未覆盖事项：十套基础非空全链；基础手机大图全链；拍立得公开整页六组合、灯箱精确焦点及三构图所有断点；全平台系统减少动态、真机触控、硬件滚轮长时流畅度；异常/并发/上传/保存发布写入状态；登录桌面独立样本及工作台手机独立样本。没有为补覆盖复制环境或修改既有草稿。历史自动化通过只能作为背景。

最多三个待确认决定：

1. 是否先批准方案1＋2，范围仅局部缺陷？
2. 下一体验切片选方案4“基础表单层级”，还是方案5“手机照片任务前移”？
