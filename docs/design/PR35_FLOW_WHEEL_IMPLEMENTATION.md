## 持续快速切换修正（2026-10-09）

### 新证据与原因

用户在上一候选反馈长时间快速切换仍卡住。浏览器复现：先向下切换，再在转场期间开始反向，每55ms请求一次输入，持续28次仍停在pricing；停250ms后才返回works。同向45次输入、实际约4.26秒也只停在pricing。纯逻辑样本持续6秒同样被忽略。未发现确定的动画完成Promise永久锁死。

原因是转场期输入覆盖了已消费方向，同时将整段手势锁为consumed。只要输入间隔小于180ms，就一直无法重新接受输入。上一轮“连续手势最多一页”的规则过严；用恒定50px来代表惯性的测试也误将主动滚动锁住。本节替代上文对应的持续输入结论，旧证据继续保留。

### 局部修正

- 转场期间不覆盖已消费方向，不排队输入；完成后新收到的反向输入立即重新累计。
- 持续同向输入需要至少3个不衰减脉冲，每次至少36px、累计至少120px，才再次切换；转场自身仍保护页面交接。
- 正文可滚动时优先原生滚动。到达边界后重新累计主动脉冲；下降幅度的尾流和小幅噪声不触发下一页。
- 产品代码只调整 `scene-wheel.ts`，同步修正并增加真实行为测试；未改视觉、内容、数据契约或调用方。

浏览器没有通用的惯性标记：恒定强输入也可能来自部分设备的惯性。这是明确的交互取舍，需要用户实体鼠标／触控板体验复核，不能声称所有硬件均已覆盖。
