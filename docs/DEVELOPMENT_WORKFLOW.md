# 开发、验收与交付流程

本文件规定稳定的操作方法；当前任务、分支、PR、授权和剩余风险见 [CURRENT_STATUS](CURRENT_STATUS.md)，续接点见 [SESSION_HANDOFF](SESSION_HANDOFF.md)。
历史记录只证明当时范围，不自动授权当前任务、合并、迁移、服务切换或部署。

## 文档职责

| 入口 | 保留内容 |
| --- | --- |
| [AGENTS](../AGENTS.md) | 稳定规则、数据保护、必要读取入口 |
| [README](../README.md) | 产品用途、当前能力及操作入口选择 |
| CURRENT_STATUS | 唯一活跃检查点、基线、授权、剩余风险、下一步 |
| SESSION_HANDOFF | 最近完成的增量及续接位置，引用证据，不复制全部历史 |
| 阶段／验收记录 | 适用日期／SHA、数据类型、环境、实测及缺口、首次失败 |
| Accepted ADR | 持续有效的不变量；改变时显式替代 |
| 仓库外本机交接 | 实际运行目录／BUILD、Windows控制入口及配置位置；不入公开仓库 |

进入任务先核对当前目录的分支、Head和未提交修改。目录名称不代表它是最新main或日常运行目录。
历史工作区不得只拼接新README后冒充同步；保留独有提交、未提交内容和被忽略的私人文件，再决定对齐方式。

## 先选择运行场景

以下是互斥场景，不是一份从上到下执行的安装清单。

| 场景 | 正确入口 | 数据与操作边界 |
| --- | --- | --- |
| 当前Windows日常 | 按私有交接先查看状态，必要时由既有Windows任务启动／停止 | 已运行不重复启停；不从Codex临时终端重新托管；不迁移／开户／导图 |
| 首次全新开发环境 | 专用PG、私有账号配置与素材根准备后，分别确认schema迁移、交互开户和构建 | 只有明确空的新目标才走初始化；不机械套用于已有Site |
| Site真实账号候选 | 闲置候选目录的匹配构建和Site Node runner，`accounts:start`使用3003 | 可能与3001共用库／素材；只读观察可以共用，写入验收必须隔离 |
| 一次性写入验收 | 专用测试PG／数据库／fixture和测试origin | 先核实实际数据库身份；不能清空长期人工样本或日常库 |
| 匿名视觉fixture | 已有受控fixture入口，标明内存修改／刷新重置／禁止保存发布 | 不冒充真实登录、数据持久化或完整业务验收 |
| Legacy回归 | 明确保留的legacy目录与显式legacy命令 | `dev`也可能占用3001；不用于恢复当前Site业务 |
| Standard Next／Stage A2 | [运行时记录](stage-a-runtime.md)、[部署runbook](deployment-bootstrap-runbook.md) | standalone与安全部署壳不自动接通账号／PG／素材；目标部署另获授权 |

人工诊断的 `platform:start` 仅在确认既有任务未运行且明确使用人工托管时执行。
不能以新端口、进程已启动或health 200证明数据隔离、登录成功或完整业务可用。

## 按改动范围验证

| 变更 | 必要检查 | 默认不重复 |
| --- | --- | --- |
| 文档／交接 | diff、相关相对链接、文档／审批契约、一次有效公开安全检查 | 产品构建、全量浏览器／DB |
| 局部文案／样式／UI | 相关测试、lint、对应桌面和手机画面；需要正式候选时构建一次 | 全站模板审查、全发布系统、数据备份 |
| 共享逻辑／异步／授权／资源／保存发布 | 相关回归及真正隔离的PG／浏览器路径，保留409、归属、权限及原超时 | 对日常账号写入，顺带重做无关模板 |
| 构建／依赖／容器／CI | 相关打包与运行契约，以及最终Head适用CI | 复用缺少目标边界的旧检查结果 |
| 合并或应用切换 | 分别按下方规则核对最终Head或运行构建 | 因Squash SHA变化或纯文档提交再次部署 |

### 命令包含关系

- `build:node`是`build`别名；无需对同一目标先后执行两次。
- `test:node-runtime`包含Next构建；`test:legacy-runtime`包含legacy构建。
- `npm test`包含多个子测试及上述两套构建／运行时检查；它不是每次局部修改的默认前置。
- `npm test`不包含真实本机账号／浏览器／生产HTTPS全部验收，不能只因总测试成功就宣称全覆盖。
- 容器上下文、代理、PG与普通构建各证明不同边界；复用产物前核对其实际覆盖，不能全部删掉。
- pre-push会执行公开安全检查；同一轮无变更时，不额外手工重复数次。CI独立环境和main push保留相应检查。

## 证据复用与记录

验收记录只需明确：基线／目标Head或BUILD、实际改动、环境与数据类型、检查和结果、未覆盖内容、下一步。
合成照片、匿名内存fixture、隔离PG持久化、真实账号只读、实体手机和目标HTTPS分别记录，不能互相替代。
保存首次失败、未解决问题和风险决定；后续成功不自动证明旧失败已修复。

相同源码／lockfile／构建配置与验收范围不变时可复用证据。
若变更影响依赖、编译配置、资产清单或目标运行方式，相关构建／运行证据失效；只补受影响部分。
记录修改、构建、相关验收、提交和CI等待的主要耗时，不为状态文字反复提交。

## 提交与CI

1. 完成授权范围，检查实际diff；保护用户未提交内容和私人素材，只stage精确文件。
2. 跑本次相关检查并普通提交／推送。用户未要求等全绿时，可交付PR及CI进行中状态，明确剩余检查。
3. CI是否采用分流，以该次运行使用的workflow和实际日志为准；未合并候选不代表main已生效。严格白名单纯文档PR的`DOCS_ONLY`只证明轻量范围，不能写成完整业务验收。
4. 代码、测试、依赖、配置、CI和未知路径，以及main push／手动运行保留完整检查。无法判定时保守执行完整检查。
5. 失败保存原始结果，按证据定位；不放宽断言、无限重跑或扩展无关实现。

## 合并验收

合并需要当前明确授权。重新核对批准Head、base、审核规则、未解决线程、冲突和该Head对应的适用检查。
明确要求五项完整实测时，文档轻量结果不足，使用已有手动完整运行入口。
Squash后核对实际提交与文件树，再按授权验证`event=push / branch=main / headSha=实际Squash SHA`；PR检查不替代main push。
是否保留或删除分支／工作区另按授权，不因合并自动清理。

## 日常应用切换

切换需要当前授权，先确认浏览器未保存编辑和进行中的上传／保存／发布已处理。

1. 只读核对Windows任务、实际进程、运行目录、BUILD及目标构建；运行目录不构建或切分支。
2. 复用与目标产品源码匹配、已验收且具备运行依赖的构建；相同产品代码不因提交SHA变化重建。
3. 使用既有控制入口正常停止应用，独立确认退出／端口释放，再切换并启动；数据库仅在确有需要时单独处理。
4. 独立核对BUILD、健康与相关实际页面；应用存活、会话和业务读取分别确认。
5. 保留经兼容核对的回退；应用回退不恢复旧数据库覆盖较新业务数据。

不默认复制node_modules、数据库、图库或完整release；备份只覆盖本次会改变的数据范围。
新候选与大产物须说明用途、大小和结束条件；已有文件处置另获精确授权。
