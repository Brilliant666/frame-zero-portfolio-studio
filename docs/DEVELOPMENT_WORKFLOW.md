# 开发、验收与交付流程

本文件规定稳定的操作方法；当前任务、分支、PR、授权和剩余风险见[CURRENT_STATUS](CURRENT_STATUS.md)，续接点见[SESSION_HANDOFF](SESSION_HANDOFF.md)。
历史记录只证明当时范围，不自动授权当前任务、合并、迁移、服务切换或部署。

## 先选择运行场景

以下是场景入口，不是一份从上到下执行的安装清单。

| 场景 | 正确入口 | 数据与操作边界 |
| --- | --- | --- |
| 当前Windows日常 | 本机交接和既有Windows状态／启停入口 | 已运行不重复启停；不从Codex临时终端另建实例，不迁移／开户／导图 |
| 首次全新开发环境 | 明确空目标后，分别准备专用PG、私有配置、schema和受控开户 | 初始化不能机械套用于已有Site |
| Site真实账号候选 | 闲置候选目录的匹配构建，`accounts:start`使用3003 | 可能与3001共用库／素材；写入验收必须真正隔离 |
| 一次性写入验收 | 专用测试数据库、素材根、fixture与origin | 先核对数据库身份；不清空长期人工样本或日常库 |
| 匿名视觉fixture | 既有受控入口，明确内存修改／刷新重置／禁止保存发布 | 不冒充真实登录、持久化或完整业务验收 |
| Legacy回归 | 明确保留的legacy目录与命令 | `dev`也可能占用3001，不用于恢复当前Site业务 |
| Standard Next／Stage A2封闭壳 | [运行时记录](stage-a-runtime.md)、[旧壳runbook](deployment-bootstrap-runbook.md) | A2工具及拒绝规则保留，不作为生产Site业务更新器 |
| 生产Site | PR50的[生产运行合同](PRODUCTION_SITE_DEPLOYMENT.md) | 正式standalone＋HTTPS＋PG／私有素材；目标部署另获授权 |

`platform:start`仅在确认日常任务未运行、明确选择人工托管时使用。
新端口、进程存在或health 200不能证明数据隔离、登录成功或完整业务可用。

## 应用更新与数据操作

**普通版本更新默认只替换应用产物，继续使用已有数据库、照片和配置。备份独立持续维护；首次部署、数据搬迁、数据结构升级与故障恢复分别处理。**

| 操作类别 | 替换／改变什么 | 保留什么 | 必要验证 | 额外备份／迁移 |
| --- | --- | --- | --- | --- |
| 仅代码提交／合并 | Git源码与记录 | 正在运行的应用、数据和配置 | 相关diff／检查；按授权验证合并提交 | 不自动部署、备份或迁移 |
| 普通应用更新 | 经验证、与现有数据和配置兼容的应用产物及app服务 | 原PG、素材卷／文件键、外置配置、账号与Published | 产物身份／平台、兼容性、ready及必要业务读取 | 沿用有效常规备份；不默认全量备份、搬数据或恢复演练 |
| 兼容性schema升级 | 显式、版本化的schema迁移及相关应用 | 既有业务内容和素材 | 隔离迁移验证，新旧应用兼容范围及失败处置 | 核对有效备份；按实际风险补范围，不隐式随启动执行 |
| 破坏性或批量数据变更 | 既有行、JSON、素材键／文件或删除语义 | 未授权数据、必要原始资料及有效恢复点 | 精确影响、隔离演练、结果一致性和恢复／向前修复方案 | 准备与影响匹配且足够新的备份及必要演练 |
| 首次部署／跨机器搬迁 | 新运行环境；选择迁入时另搬数据库与素材 | 来源数据与配置；同一安装搬迁保持ID／引用／发布关系 | 身份权限、结构角色、持久化、数据关系及上线基础保护 | 空站不强制迁本地图库；搬迁需一致备份／恢复验证 |
| 故障恢复 | 按故障范围恢复数据／文件／配置或环境 | 可恢复的新业务与故障证据 | 恢复点适用性、数据损失范围、一致性和可用性 | 专项恢复流程，不冒充普通app更新或应用回退 |

普通更新要求新旧应用与现有数据库、已存内容格式、素材及运行配置兼容；不批量重写数据，不改变持久化位置、卷归属、数据库身份或关键密钥策略。
不能只看有没有新增SQL文件：JSON兼容性、素材键／路径／格式、删除行为、连接目标／角色权限、密钥、PG大版本及其他基础设施变化都要纳入分类。
存储搬迁、数据库大版本升级走专项操作。兼容性不明时指出具体疑点，只补必要验证，不自动开展全项目审计或全量备份。

## 普通应用更新

先分“发布准备”和“现场切换”，能够提前完成的工作不全部塞进停机窗口。

1. 发布准备：确定目标版本、匹配的测试与产物；核对源码／锁文件／构建配置、目标平台、运行方式及验收范围。输入匹配时复用已有产物和有效证据，相关输入变化后只补受影响部分。
2. 切换前：确认目标环境、原PG／素材／配置身份、回退应用与当前数据的兼容性；处理未保存编辑及在途上传／保存／发布。
3. 现场切换：用既有受控入口正常停止并确认原app退出，再启动目标app；沿用数据库、照片和外置配置。无相关变化时不重启PG、代理或其他项目服务。
4. 验收：核对实际BUILD／镜像ID、readiness和必要业务读取，成功后再报告完成；保留一套经兼容确认的上一应用版本。

这不授权在运行目录git pull、覆盖构建、修改共享依赖、重新初始化／开户／导图／发布，或复制完整运行环境。
不因Squash SHA变化、文档提交或PR合并自动部署；不承诺所有更新固定若干秒完成，不用强杀代替正常停止。

当前Windows日常继续使用下方[日常应用切换](#日常应用切换)及仓库外控制入口，不强制改用Docker。
生产Site目前可按[普通应用版本更新](PRODUCTION_SITE_DEPLOYMENT.md#普通应用版本更新)人工执行受控Compose操作；后台一键更新、镜像发布渠道和专用Site更新器尚未实现。

## 备份与首次部署

- 正式保存有价值数据后，常规备份与恢复保障独立维护，频率、保留、外部存放与验证按数据价值及恢复目标确定。本轮规则不代表自动备份已经实现。
- 已有有效备份可复用，不要求每个普通版本重新证明整套灾备能力，也不默认暂停更新等待整套图库备份。
- 高风险操作前核对备份的新鲜度、范围及恢复方式；不足时只补所需范围。不能写成“代码更新永远不需要备份”。
- 持久卷不是备份，保留旧应用镜像也不是业务数据备份。

首次生产可选“空站开始，之后正常上传正式作品”或“一次性迁入已有本地账号／照片／草稿／Published”。
仅第二条路径需要搬现有本地业务数据；空站仍须显式准备schema、最小权限角色与受控账号。
无论选择哪条路径，在生产成为真实权威写入环境前都须满足必要身份、安全、持久化与基础备份恢复保护；不能用本策略豁免首次上线要求。

## 应用回退与授权

旧应用与当前数据库、内容格式、素材及配置仍兼容，才可切回旧应用；不能以旧数据库快照覆盖更新后产生的新业务内容来完成应用回退。
不兼容时停止回切，给出相应数据恢复或向前修复方案。容器重建不是跨版本回退验收，不承诺任意版本无损自动回退。

用户授权指定环境更新到指定版本后，范围内的常规预检、正常停止、启动与验收可连贯完成，不逐步骤反复审批。
合并PR不自动授权部署，文档也不提供永久部署授权；范围外破坏性变更、真实搬迁或影响其他项目时说明实际影响并取得对应授权。
未执行的旧计划不自动接续。每次在既有交付记录简述目标版本、操作类别、数据影响、验证结果和回退条件即可，不另建逐版本长报告。

## 按改动范围验证

| 变更 | 必要检查 | 默认不重复 |
| --- | --- | --- |
| 文档／交接 | diff、相关相对链接、文档／审批契约、一次有效公开安全检查 | 本机产品构建、全量浏览器／DB |
| 局部文案／样式／UI | 相关测试、lint、对应桌面和手机画面；需要正式候选时构建一次 | 全站模板审查、全发布系统、无数据影响的全量照片备份 |
| 共享逻辑／异步／授权／资源／保存发布 | 相关回归及真正隔离的PG／浏览器，保留409、归属、权限与原超时 | 日常账号写入、顺带重做无关模板 |
| 构建／依赖／容器／CI | 相关打包与运行契约，以及最终Head适用CI | 复用缺少目标边界的旧检查 |
| 合并或应用切换 | 分别核对最终Head或运行构建，按本次操作类别处理数据风险 | 因Squash SHA或纯文档提交再次部署 |

### 命令包含关系

- `build:node`是`build`别名，不对同一目标先后执行两次。
- `test:node-runtime`包含Next构建；`test:legacy-runtime`包含legacy构建；`npm test`包含多组子测试及上述构建／运行时检查，不是每次局部修改的默认前置。
- `npm test`不包含全部真实账号／浏览器／生产HTTPS验收；不同边界的证据不能互相冒充。
- pre-push会做公开安全检查；同一轮无变更时不额外手工重复数次，CI独立环境仍保留相应检查。

## 证据复用与记录

说明基线／目标Head或BUILD、改动、环境与数据类型、检查结果和未覆盖项。
合成照片、内存fixture、隔离PG、真实账号只读、实体手机和目标HTTPS分别记录；保留首次失败、未解决问题与风险决定。
相同源码／锁文件／构建配置、平台及验收范围可复用；依赖、资产清单或运行方式变化后更新相关证据，不为状态文字反复提交。

## 提交与CI

1. 完成授权范围，只stage精确文件，保护未提交内容和私人素材。
2. 跑相关检查并普通提交／推送；用户未要求等全绿时可交付PR及CI进行中状态，不把提交完成说成全部成功。
3. 严格白名单纯文档PR的DOCS_ONLY只证明轻量范围，不冒充完整业务验收。
4. AGENTS等规则文件、代码、测试、依赖、配置、CI、未知路径和main push／手动运行按既有策略走完整检查；不为文档任务改分类器。
5. 失败保留原始结果，按证据定位，不放宽断言、无限重跑或扩展无关实现。

## 合并验收

合并需要当前明确授权；核对批准Head、base、审核规则、未解决线程、冲突和适用检查。
明确要求五项完整实测时，DOCS_ONLY不足；使用已有手动完整运行入口。
Squash后核对实际提交与文件树，再按授权验收event=push／branch=main／实际Squash SHA；是否删除分支或工作区另按授权。

## 日常应用切换

切换须有对应授权，并确认未保存编辑与在途操作已处理；该范围内不对每个常规步骤重复审批。

1. 只读核对Windows任务、进程、运行目录、BUILD及目标构建；运行目录不构建或切分支。
2. 复用匹配且已验收的构建，不因提交SHA变化重复重建。
3. 用既有控制入口正常停止app，独立确认退出／端口释放，再切换并启动；无确切需要不启停数据库。
4. 独立核对BUILD、ready及相关页面／业务读取。
5. 保留经兼容核对的上一应用；回退不能回灌旧数据库覆盖较新内容。

不默认复制node_modules、数据库、图库或完整release；新大产物说明大小与结束条件，已有文件处置另获精确授权。
