## PREVIEW_COMPOSITION_POLISH_01：新版图集内部构图

本轮仅在新版已保存工作区的照片场景启用运行时 `composedPhotos`，新后台草稿预览走同一组件；首页 covers、旧九图和旧临时原型仍用原布局。文档结构、两套 API、记录、revision、重点照片及成员顺序均未改动，也没有真实 PUT。以下历史中“尚未打磨”的描述保留为阶段记录，不代表本轮没有做渲染调整。

以既存九图为基线，用主簇左侧锚点与两张错落辅助照片、右上镜像次簇、右下局部组合替换中心主图加左右两排。面积层级来自重点及稳定的顺序角色，不以横竖方向判定重要性；几何组合不是持久化分组或语义分类。真实比例、完整纸框和旋转边界参与计算，有限候选扩展二维场景，保持输出 ID 与 DOM/大图顺序。十张及以上默认框选重点附近七张，FIT 才切全图；手机按原顺序保留纸框、轻微错落与正常页面滚动。

图集卡片只留小编号，点击提示集中在标题区；移除内部水印与连线，弱化纸面点阵和阴影。标题区、桌面控件与照片画布分开，避免遮挡。样式仍只作用于新版照片运行时标识，样式模块缩名为 `collection.module.css` 减少重复生成的类名前缀。临时配置界面补显式 development 条件，使生产构建去除原本不可达的开发 UI；本地旧原型行为保留，没有提高任何预算。

真实浏览器以同成员、顺序、重点及 1440×900、1280×720、390×844、320×720 CSS viewport，分别记录默认进入与 FIT 对照，等待镜头过渡完成，不手工拖到“最佳角度”。九图、十三图及第三图集，以及匿名四十图／全横全竖 fixtures 均有本机截图。匿名四十图桌面初始约 56%、FIT 约 27%，完整成员可达，末张与首尾循环、浅色大图、关闭焦点、返回镜头、手机滚动及窄后台容器均做实测。提供顺序截图，没有录制视频。私人证据只保存在仓库外，不上传 Git 或 CI。

## PREVIEW_WORKSPACE_01：本轮实际保存决定

本轮人工授权解除旧原型“只在内存”的限制，但只针对独立本地工作区；不修改冻结的 `SiteDocumentV1`，不定义正式 V2、Site、多租户或 Publish 系统。下方旧设计原型记录作为历史保留，不能再据此认为 `/preview` 无保存能力。

| 入口 | 数据及职责 |
| --- | --- |
| `/`、`/admin`、`/api/site-content` | 原版十一模板和后台，继续使用旧记录 `site_settings.id=1`、旧保存契约 |
| `/preview` | 新版已保存拍立得图集；不读取其他标签页后台草稿，不显示临时配置或模板选择 |
| `/preview/admin` | 新版资料、图集、套餐联系编辑；自己的 saved/draft 与保存快捷键 |
| `/api/preview/site-content` | 严格解析 `PreviewPortfolioDocumentV1`，只访问服务端固定记录 `site_settings.id=2601` |

`npm run dev` 仍启动 vinext/workerd 和现有 loopback 素材 companion。新版记录复用项目本地 `.wrangler` D1 SQLite 持久化，不新建云数据库、不双写 JSON。记录中的 envelope 含服务器维护的 revision；更新时间由服务器维护。无记录 GET 返回明确未配置且不写入；损坏、未知版本和读取失败拒绝继续。PUT 完整校验后以数据库原文 CAS 原子写入，旧版本返回 409，后台保留草稿。限额为 512 KB、30 个图集、每图集 500 张；封面可独立于成员，重点照片必须属于成员。

安全由开发启动配置、每次启动随机服务器证明及 Vite 的实际 loopback socket 检查共同建立，外来证明头先移除。写入另检查同源 Origin 和 JSON。页面与 API 私有、不缓存。Standard Next production/container 不拥有开发绑定，新路由服务端关闭，不能据本地保存宣称生产持久化完成。

首次打开 `/preview/admin` 可从空稿创建，或明确点击“一次性复制原站资料”进入草稿；仅复制基础资料、套餐、联系白名单，不复制旧作品和模板集合，仍需点击“保存新版修改”。旧内存原型可导出图集 JSON 后显式导入；不能恢复已丢失的内存。保存期间继续编辑不会被回包覆盖；发生冲突先导出草稿，再重新读取并人工处理。保存不是发布。

新旧共用素材库、不复制文件。新增引用需服务端核对当前可用素材；已存缺失/回收引用保留，不因素材加载失败而删关系。展示跳过不可用照片并提供空状态，素材恢复后重新解析。旧素材管理会额外核验新版含隐藏图集的封面、重点和成员；未知引用状态阻止回收操作，有引用明确确认。回收仍影响双方可见性，不等于内容全部隔离。

验证采用隔离的真实 SQLite 数据库检查双向写入、CAS 竞争、损坏和重开；本机浏览器检查新后台保存、刷新、项目开发服务重启及真实回读；旧站以逻辑内容和更新时间核对，不以 SQLite 文件物理哈希判断。生产构建另测新路由 fail closed。私人照片、ID、备份、数据库和截图不进入 Git。

本轮实际验收通过：经用户确认无手工临时改动，以共享素材建立 9、13、10 张的三个演示图集（不代表正式分类），通过后台保存；刷新和明确识别本项目进程后的服务重启均回读一致。双标签冲突保留草稿，保存中继续编辑不被响应覆盖，只修改一个图集时其余不变；旧站逻辑内容及更新时间保持不变。1440×900、390×844、320×720 CSS viewport 验证完成，旧十一模板浏览器回归无页面异常，缺失素材模拟不删引用。完整 `npm test`、lint、diff check 和两套构建预算通过；Standard Next HTTP 检查三个新版入口均 404，伪造证明头不能开启。截图及本机回读证据保留在仓库外，不随 PR 上传。

视觉继续沿用现有场景，不重做布局算法。保留 `PREVIEW_COLLECTION_COMPOSITION_POLISH_PENDING`、`HUMAN_VISUAL_APPROVAL_PENDING` 和 `FROZEN_AT_REPO_SIDE_BOOTSTRAP_READY`，本 PR 保持 Open + Draft。

## 历史：只读内存原型

状态：`HUMAN_VISUAL_APPROVAL_PENDING`；保存能力：`COLLECTION_PERSISTENCE_NOT_IMPLEMENTED`。浏览器验收结果以本轮实际检查记录为准。

本轮纠偏保留拍立得星图，把首页单图入口升级为图集封面入口。首页与图集内部均使用可拖动、缩放的拍立得星图；点作品进入固定浅色大图，切换范围限于当前图集。取消上一轮画册／纵向写真两种排版及样式选择器，不增加新的封面展示层。

运行 `npm run dev` 后访问 `http://127.0.0.1:3001/?template=polaroid-field&collections=preview`。该入口仅在开发构建及 loopback 主机生效；未开启时保留原九图体验。右下角“临时配置”打开浮层，只修改 React 内存，刷新即丢失，不触发保存请求。三个初始名称是可编辑示例，未预先分配照片；显式测试分组只用于验证交互，不代表真实分类。

首页卡片代表 Collection，图集中的卡片代表 Asset。封面、成员顺序与重点照片分别配置；重点照片默认取当前图集第一张可用照片，可临时指定另一张，失效时回退第一张。封面可独立选片与裁切，内部作品及大图保持自然比例和完整画面。增加照片时扩展星图，初始视角保留可读尺寸，用户可主动查看全图。

原型只读现有 `/photos/library-manifest.json` 与 Asset 变体；真实照片、素材清单、Asset ID、个人路径及截图不随此文档提交。技术测试覆盖数量、比例、边界及成员隔离，不替代人工视觉验收。

桌面复用原星图纸张、胶带、卡片、连线与画布控制。动态布局计算完整白边、标题和旋转边界，按明确的首图／指定重点形成视觉重心；几何位置不重写看图顺序。手机在同一星图中纵向错落排列，保留原比例、胶带、旋转和连线，随页面自然滚动；FIT 适应宽度，方向与缩放控件保持可达。桌面与手机分别记住每个图集的画布视野。

本地真实浏览器验证使用 1440×900、1280×720、390×844、320×720 CSS viewport，包含同照片参考对照、9 张混排、13 张及竖图较多图集、浅色大图与连续返回。另以 40 张匿名合成图片实际验证画布、FIT 完整边界、末张大图、循环计数、焦点与位置恢复；未将数组测试等同于视觉验收。真实照片及匿名浏览器截图均留在仓库外的本机证据目录。

补查确认手机首页与图集独立恢复页面滚动位置，公开原型浏览器后退保持恢复；切换套餐再回作品不会因隐藏画布的零宽度测量重置视野。浏览器检查未发现写入请求或页面异常。首页聚焦构图允许卫星封面部分延伸至边缘，可用“查看全部图集”完整查看；多图 FIT 是总览，不承诺缩成一屏后仍清晰。手机长场景保留错落节奏，但长图集需要页面滚动，这些取舍仍待人工视觉批准。

## 后续正式保存仍需回答的九个问题

1. **最小字段。** 需要稳定 Collection ID、Site ID、标题、可选介绍、可见性／排序、有序 Asset ID、独立封面引用和封面裁切／焦点。重点照片是否持久化待决定；本轮没有展示样式字段，素材字节和路径不进入这些字段。
2. **归属与位置。** 图集应是 Site 所有的领域数据，参与未来 Draft／Revision／Publish 生命周期；本原型不选定数据库表或序列化结构。
3. **旧数据兼容。** 原九槽及现有十一模板契约保留。后续适配器不得自动把旧槽位解释为摄影师真实分类。
4. **冻结文档。** `SiteDocumentV1` 不变；图集需要之后的版本化产品及架构决定，本轮不增加字段、变体 ID、迁移或保存 API。
5. **引用与复用。** 成员与封面使用稳定 Asset ID；同一照片可进入多个图集而不复制文件。顺序归属图集，不归属素材。
6. **删除和缺失。** 正式后台删除前应展示引用影响。隐藏图集退出公开导航；缺失素材跳过，失效封面回退首个可用成员或空状态。本轮仅演示安全显示。
7. **封面与正文。** 封面裁切是图集展示状态，正文及大图保留自然比例。正式后台应分别编辑封面与成员；当前验证面板不代表后台最终设计。
8. **托管 ID。** 托管解析器沿用稳定 Asset ID。正式图集引用不能使用本地 `/photos/` URL、导入位置、文件名或哈希替代领域 ID。
9. **适配和迁移成本。** 正式接入需要版本化适配器、前后台渲染、修订验证、引用感知删除及人工认可的旧槽迁移选择。本轮不进行自动分类或迁移。
