# ADR 0004：有限发布历史与相同内容复用

- 状态：Accepted（2026-10-10，用户确认“保留回退，减少重复记录，弱化版本号展示”，并授权清理已有历史）
- 范围：本站三个独立内容空间的发布记录；不改变 Site 授权、内容 schema、资源归属或公开读取入口。

## 决策

1. 草稿内部 revision 继续用于并发控制，不为每次保存建立草稿快照。
2. 发布仍校验 owner、模板授权、预期公开指针、准确草稿收据和素材可用性。比较实际公开投影及素材集合；相同内容复用本站同空间的不可变快照，不新增重复记录。
3. 历史保留每个 Site、每个内容空间最近 10 份不同内容，并额外保留当前公开快照。当前指针绝不因保留策略而切换。空间之间不共享内容或合并记录。
4. 已存快照仍禁止 UPDATE。原先无条件禁止 DELETE 的规则仅增加受限保留策略清理：必须在数据库中复核保留集合与当前公开保护，不能通过关闭触发器或任意删除接口清理。
5. 相同内容可能对应不同草稿 revision。接口单独返回服务端确认匹配的草稿 revision；前端不得仅因版本号相同或公开指针未变，就认定丢失响应的发布成功。回退始终匹配用户选中的确切记录 ID。
6. 常规界面显示保存／发布状态、模板和时间，技术版本号放在详情。历史是恢复点列表，不承诺保存每次重复点击的审计日志。

## 边界与恢复

本决定细化 North Star 中“immutable revision”的生命周期：保留期间内容不可修改，并非永久保存全部重复副本。此前无需删除权限的普通读写路径不增加任意删除能力。素材文件、草稿、Published 指针不在历史清理范围内。

本次既有历史清理在私有完整数据库备份及精确记录导出后执行，只操作授权 Site 的重复／超额历史。备份不能代替当前指针保护或跨站拒绝。清理前后核对精确计划、草稿、指针、其他 Site 及素材；不回灌整库覆盖后续编辑。

新规则在新应用部署后才持续生效；单次清理旧应用的数据库不等于部署新应用。合并、日常应用切换和公网部署仍需分别授权。
