# ADR-0002：Site 是租户边界

- 状态：Proposed
- 日期：2026-07-12
- 决策人：待维护者确认
- 关联 Phase / Epic：Phase 0 / Epic 01
- 关联 PR / Issue：本 ADR 的引入 PR

## 背景

当前私人站把全部内容保存在 `site_settings(id = 1)` 的单条 JSON 中，所有请求默认访问
同一份站点数据。这个实现适合单站原型，但无法为未来的多站点、成员协作、素材隔离、
修订发布和域名解析提供明确边界。

[`NORTH_STAR.md`](../NORTH_STAR.md) 已规定系统核心实体是 `Site`，并要求所有资源查询在
数据库层包含 `siteId` 或等价租户条件。本 ADR 固化这一边界，避免后续
`SiteDocumentV1`、repository、授权和迁移工作分别推断不同的租户语义。

## 决策

### 1. Site 是最小的数据所有权边界

用户不是租户。一个用户未来可以拥有或加入多个 Site，一个 Site 也可以有多个成员。
内容修订、素材、素材变体、发布记录、域名、上传任务和配额等租户资源都必须归属于
一个明确的 `siteId`。

`siteId` 是不可变、不可由展示字段推导的随机 UUID、ULID 或等价标识。站点的 slug、
展示名称、域名、owner 邮箱和摄影师品牌名都不能作为实体身份。

### 2. SiteDocumentV1 是可移植内容，不承载租户身份

`SiteDocumentV1` 描述可发布的摄影主页内容和构图。它不嵌入以下数据：

- `siteId`、owner 或成员关系；
- 登录会话和权限；
- 对象存储 key、原始文件路径或固定 CDN URL；
- 发布指针、修订作者或审计信息。

文档由带 `siteId` 的 Site Revision 或等价持久化信封保存。文档中的构图只引用
`assetId`；解析资源时必须同时提供已授权的 `siteId`，并确认资源属于同一 Site。

### 3. 授权先产生站点范围，再访问 repository

写入或读取非公开租户资源前，应用层必须先得到包含 `siteId`、用户身份和权限的
`AuthorizedSiteContext`。repository 方法必须把该 `siteId` 放入数据库查询条件。

禁止先按全局资源 ID 读取，再在应用层比较 `resource.siteId`。批量查询、更新和删除也
必须在同一个数据库操作中带站点范围，不能依赖调用者事后过滤。

公开页面可以通过可信的 Host/域名映射解析 Site，但解析结果仍必须转换成明确的
`siteId` 后再读取已发布内容。Host 不是下层 repository 的隐式全局状态。

### 4. 当前私人站通过单站迁移获得真实 siteId

Phase 0 迁移器将为当前私人站生成并持久化一个随机、不可变的 `siteId`。该 ID 在一次
安装内保持稳定，但不能作为所有自托管安装共享的源码常量。

兼容期内保留 `site_settings(id = 1)` 作为旧数据回退来源。新模型读取成功前不得删除旧
记录；迁移必须支持 dry-run、备份、迁移报告和失败恢复。具体表结构、双读切换与旧表
保留期由后续 migration PR 决定。

## 方案对比

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| Site 作为租户边界 | 支持多站点所有权、成员协作、独立发布和资产隔离 | 所有数据访问都必须显式携带站点范围 | 采用 |
| User 作为租户边界 | 初期查询简单 | 无法表达一个用户多站点或一个站点多成员 | 拒绝 |
| 把 `siteId` 写进 SiteDocumentV1 | 导出文件看似自描述 | 内容与部署身份耦合，复制站点时容易错误继承所有权 | 拒绝 |
| 先按资源 ID 查询再检查 `siteId` | repository 接口较少 | 容易产生越权、竞态和批量接口漏检 | 拒绝 |
| 每层隐式读取 Host 推断 Site | 调用参数更少 | 后台任务、预览和自定义域名场景不可靠，难以测试 | 拒绝 |

## 数据与兼容性

- 本 ADR PR 不修改数据库、D1 记录、JSON 格式或 API 行为。
- 后续 Site/Revision/Asset 表必须以 `siteId` 建立查询范围和必要索引。
- 当前 `site_settings(id = 1)` 在兼容期内保持可读，不在引入新表的同一 PR 中删除。
- 单站迁移失败时继续读取旧记录；新模型写入不得覆盖旧 JSON。
- `siteId` 生成、迁移、双读和回滚必须由带行为测试的独立 PR 实现。

## 安全与租户边界

- 认证供应商不在本 ADR 中决定；认证结果必须先转换为站点授权上下文。
- owner/editor/viewer 的现有权限基线不在本 ADR 中改变。
- 任意资源访问必须把 `siteId` 放入数据库查询条件，而不是读取后校验。
- 未登录、无权限、跨站点 ID、批量混入其他 `siteId` 都必须成为后续授权测试。
- 日志可以记录内部 `siteId`，但不得记录原图路径、存储凭证或完整敏感内容。
- 公开 Asset ID 的随机生成与指纹策略由 ADR-0008 进一步决定。

## 运维影响

- 本 ADR 不新增环境变量、服务或云厂商依赖。
- 自托管安装需要在迁移时生成自己的默认 `siteId`，不能复用仓库内公共常量。
- 未来日志、缓存键、后台任务和发布记录需要显式携带 `siteId`。
- 数据库和对象存储的具体参考实现由其他 ADR 决定。

## 验证

- 本 ADR 与 NORTH_STAR 的 Site、SiteDocument、授权和 Phase 0 迁移约束逐项核对。
- 文档 PR 运行 `git diff --check`、`npm run lint` 和 `npm test`。
- 后续实现必须增加旧数据升级、迁移失败恢复、未授权和跨站点访问测试。
- 在跨租户行为测试完成前，不得宣称多用户或多站点隔离已完成。

## 后果

正面影响：

- SiteDocumentV1 可以在不携带所有权和部署细节的情况下导出、复制和版本化；
- repository、授权、缓存、任务和资产解析共享同一租户范围；
- 当前私人站可以先迁移为一个真实 Site，再渐进增加多站点能力。

接受的代价：

- repository 和服务层接口会显式增加 `siteId` 或 `AuthorizedSiteContext`；
- 迁移、索引、测试和可观测性都必须覆盖站点范围；
- 不能用全局资源 ID 查询或展示字段作为快捷身份。

本 ADR 不代表多用户 SaaS 已实现，也不授权提前开放在线注册、多站点创建或成员管理。
